# Route search benchmark

Generated by `scripts/bench_route_search.py`. Do not edit by hand: rerun `make bench`.

- MySQL: 26.7.0 (image `mysql:26.7`, the one CI uses)
- Flights: 200,000 between 60 airports, seed 42 (`scripts/seed_flights.py`)
- Search: route + departure window 2030-06-15 to 2030-06-21, limit 100, ordered by departure (what the frontend sends)
- Latency: median of 20 calls after 3 warm-up calls, query and row fetch only, from the host to MySQL in Docker
- Rows examined: `performance_schema.events_statements_history.ROWS_EXAMINED` for `PS_CURRENT_THREAD_ID()`, identical on every timed call
- Without the index: `ix_flights_route_start_time` dropped and a `departure_airport` index created, as in the migration's downgrade. With it: recreated as `(departure_airport, arrival_airport, start_time)`, as in migration `2b19d14b47a1`
- Host: Darwin arm64, Python 3.14.3, 2026-10-14

## Reproduce

```bash
make bench
```

Needs Docker and uv. It starts a fresh MySQL container on port 3317 (`BENCH_PORT` changes it), seeds it, measures, writes this file and removes the container.
